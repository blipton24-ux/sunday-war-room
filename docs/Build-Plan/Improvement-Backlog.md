# Improvement Backlog

Known gaps and upgrades we have chosen to defer, with the evidence for each. It is a list of **things to improve**, not decisions: anything that needs a choice follows [ADR-003](../Decisions/ADR-003-Documentation-Standard.md) and becomes an ADR when picked up. Questions that block a build step live in [Open Questions](../Specs/Open-Questions.md) instead.

**How to use it**
- Add an item the moment we notice one (with the measurement or incident behind it), even if we won't act soon.
- IDs are permanent (`M-` model, `U-` UI, `P-` platform/ops). Reference them in commits and ADRs.
- When an item is picked up, link the ADR or PR in the Status column; when it ships, move the row to **Done** at the bottom.
- Model changes follow [ADR-034](../Decisions/ADR-034-Ship-Model-v1-Upgrade-Later.md): a new version ships only if it beats model 1.0.0 on held-out weeks, including the startable-player slice, and reusing any technique from the earlier project needs its own approval ([ADR-002](../Decisions/ADR-002-Fresh-Build.md)).

Priority: **High** = fix before it can mislead a user or lose data · **Med** = clear user-visible gain · **Low** = polish or later phase.

## Projection model

Baseline to beat (held-out 2024 / 2025, weeks 5–18, full PPR, average miss in points; see [ADR-034](../Decisions/ADR-034-Ship-Model-v1-Upgrade-Later.md)): startable players 6.35 / 6.45 for model 1.0.0, against 6.26 / 6.50 for a plain season average and 5.78 / 5.83 for the earlier project's model.

| M-03 | **Depth-chart rank adjustment for RB / WR / TE** (v1 adjusts backup QBs only). | The earlier project found a monotonic residual by depth rank at every position and improved ordering everywhere | Med | ADR-002 approval; needs depth-chart data ingested (nflverse `load_depth_charts`, shape changed in 2025) | Open |
| M-04 | **Project team defenses from the opponent's betting total** instead of the defense's own history. | v1 defense rank correlation is 0.17 (held-out 2025); the earlier project measured a defense's own recent scoring as no better than a constant | Med | ADR-002 approval; needs a betting-line source | Open |
| M-05 | **Better starting point for players with no history** (rookies, veterans back from a missed season): draft round and depth rank instead of a flat 30th-percentile value. | v1 treats a first-round rookie and an undrafted one the same; the earlier project's fitted values differed by roughly 3–4x between them at RB, WR and TE | Med | ADR-002 approval; needs draft-pick data (`load_draft_picks`) | Open |

| M-07 | **Correlated simulation**: a QB and his own receivers should move together; v1 draws every player independently. | The earlier project measured QB↔WR +0.20 and QB↔TE +0.21 at player level, and near zero for two receivers on one offense | Low | ADR-002 approval; changes win probabilities, not projections | Open |
| M-08 | **Ranges fitted to each league's scoring.** Ranges are fit in half-PPR and applied to every league (a v1 simplification, stated in the Projection Model spec). | Scoring changes the spread of outcomes, and range coverage for other scoring formats hasn't been measured | Med | Refit per scoring family, or scale by projected points; verify 80% coverage per family | Open |

| M-14 | **Weekly auto-refit of ranges with a promotion gate** (listed in the Projection Model spec under later upgrades). | Calibration is fitted once, by hand, from the backtest | Low | Needs M-09 and enough live weeks | Open |
| M-15 | **Smarter rest-of-season value (P4).** P2 ships a simple version: the weekly model carried across the remaining schedule (byes, opponents, playoff weeks x1.5, short injuries for one game, IR for 4 weeks). | M-18 | **IDP (individual defensive player) slots on ESPN.** An IDP starter is stored as bench and shows "not projected". | P3 mapping | Low (P4) | The P4 IDP work | Open |
| M-19 | **ESPN players we can't match to our player list.** The first real ESPN sync logged 2 unmapped players (ESPN ids 4360238, 4427728); they are skipped rather than guessed, so they show no projection. | M-16 | **Weak spots to watch**: running backs are slightly worse than the season-average baseline (MAE 4.12 vs 4.08); quarterbacks, kickers and defenses order poorly (rank correlation 0.45 / 0.13 / 0.17). | [Backtest Report](Backtest-Report.md), held-out 2025 | Info | Re-read after each model change | Open |
| M-20 | **Injury marking is strict on purpose.** A game counts as spoiled by an injury only when snaps collapsed *and* the injury report or a reserve listing confirms it at the next game. An injury with neither (a player who simply misses a game and is not on the report) is not marked, so some spoiled games stay in the numbers. Loosening it risks flagging benchings (the first version flagged two replaced quarterbacks). | P4 hand check, 2025: 80 of 367 snap collapses marked; see [P4 Build Plan](P4-Build-Plan.md) | Low | Only if a model idea turns out to be hurt by the leftover noise | Open |
| M-21 | **Wind in the backtest is the wind recorded for the game, not a forecast.** `wind_penalty` reads the nflverse schedule's `wind` column, which is filled in after the fact. A forecast available before kickoff is noisier, so the backtest overstates what the idea would do live. | `load_game_context` in `api/app/sources/nflverse.py`; the K, QB and TE tuners each picked a wind setting | Medium (before any wind setting ships) | A forecast source and a decision on timing (ADR-003); or drop wind | Open |
| M-22 | **The live path has no game context yet.** Betting lines, roof, rest days, team scoring strength, draft round, nflverse expected points, depth-chart tiers and the injury/reserve lists reach the model only in the backtest (`Extras`, `with_round_2_columns`). An idea that reads them cannot ship until the weekly compute job loads and stores the same facts before kickoff. | `project_week(..., extras=None)` in every live caller | High if such an idea is kept | Schedule lines stored at ingest; a refresh near kickoff | Open |
| M-23 | **Split opponent factor goes neutral when a league average is zero.** With `def_run` on, a position whose league-wide rushing points allowed are exactly 0 gets no opponent factor at all, even for a player whose points are all from the passing game. It cannot happen on real seasons after week 1 (receivers always have some rushing), so results are unaffected. | Found writing `test_model_ideas.py` | Low | Use the part of the game the player has when the other has no average | Open |
| M-24 | **Goal-line and red-zone usage.** How often a back gets the ball inside the 5 (and a receiver or tight end is targeted inside the 20) is a strong touchdown signal the weekly stats don't carry. Proposed for RBs in P4 round 2 and deferred by the owner (2026-11-13). | Weekly nflverse stats have no field-position split; play-by-play does (`load_pbp`, about 100 MB a season) | Medium (P4 round 2 follow-up; also serves WR/TE red-zone ideas) | A play-by-play loader that counts carries and targets by field position per player-game | Open |
| U-17 | **Accuracy page version picker.** The API now takes `?model_version=` and lists `available_versions`, but the page still shows only the current version, so right after a model version bump it looks empty until its first graded week. Add a version switch (or a "since 1.1.0" note). | M-01 (P4 Stage 1) | Med (before the first version bump) | Design (P6) | Open |
| P-18 | **mypy can't run on this Windows machine** (Smart App Control blocks its compiled files, see P-02), so type errors only showed up in CI. Run it in a Linux container instead: `docker run --rm -v "$PWD/api:/src:ro" python:3.12-slim-bookworm sh -c "pip install -q uv && mkdir /work && cd /src && tar --exclude=.venv --exclude=__pycache__ -cf - . | tar -xf - -C /work && cd /work && uv sync --frozen --extra dev -q && uv run mypy app"` (found 5 real errors in P4 code before CI did). | P4 Stage 1 | Low | A script or Make target | Open |
